# 宠馨智后端落地与部署清单

更新日期：2026-09-21

## 1. 当前已经具备

- 单一 Node.js API 服务，供微信小程序和管理后台共用。
- `pet_owner / doctor / admin` 三种角色和权限判断。
- 宠物、病例、护理方案、每日任务、打卡、提醒、医院绑定、知识库和审核相关接口。
- Supabase/PostgreSQL 数据库迁移文件及行级权限策略（RLS）。
- 微信 `code2session` 登录后端逻辑，AppSecret 只在服务端使用。
- OpenAI 兼容格式的大模型调用、知识检索、医嘱拆分和打卡异常分析。
- 私有病历文件桶初始化脚本。
- Docker 部署文件、环境变量预检、接口限流、健康检查和最小自动化测试。

这些是“可部署代码”，不等于已经连接真实云服务。

## 3. 必须由项目负责人本人完成的事项

这些动作涉及实名认证、付费、主体责任或保密凭证，开发者不能代替负责人完成：

1. 注册并认证微信小程序，取得 `AppID` 和 `AppSecret`。
2. 购买或确认正式域名，完成中国大陆需要的 ICP 备案，并配置 HTTPS。
3. 注册云服务账号并实名认证、付款；可先选腾讯云轻量服务器或同类容器服务。
4. 创建 Supabase 项目，妥善保存项目地址、Anon Key、Service Role Key 和 JWT Secret。
5. 创建大模型平台账号、开通计费并取得 API Key。首期建议使用支持 OpenAI 兼容接口的通义千问服务。
6. 确认主体名称、客服电话、隐私联系人，并审核隐私政策和用户协议。
7. 确定合作医院及医生，收集并审核真实资质；不能使用未经合作方授权的信息。
8. 在微信公众平台配置 `request/uploadFile/downloadFile` 合法域名和订阅消息模板。

不要把 `Service Role Key`、微信 `AppSecret`、模型 API Key 发到聊天或提交进 Git。负责人应在自己的电脑或云平台控制台中填写。

## 4. 负责人完成账号后，可由开发者继续完成

1. 检查本地 `.env.api` 是否完整（不显示密钥内容）。
2. 执行数据库迁移并检查 RLS。
3. 创建私有病历 Bucket 和存储策略。
4. 设置一次性 `ADMIN_SETUP_TOKEN`，通过独立Web后台的“首次创建管理员”页面建立自己的管理员邮箱和密码；成功后删除该环境变量并重启API。也可使用 `pnpm admin:bootstrap` 在服务器端建立。
5. 部署 API Docker 容器、绑定 HTTPS 域名。
6. 发布管理后台并限制管理员权限。
7. 把小程序接口地址切换为正式 API。
8. 完成微信真机登录、角色跳转、宠主—医生护理闭环测试。
9. 接入订阅消息、定时任务、监控、备份和恢复演练。
10. 用 1 家医院、1 名医生、10–20 只真实确诊宠物做 30–60 天封闭试点。

## 5. 推荐实施顺序

### 阶段 A：云资源就绪

负责人创建：Supabase、小程序、模型平台、域名和云服务器。此阶段不录入真实病例。

### 阶段 B：技术联调

执行迁移、创建 Bucket、部署 API、配置合法域名。用虚构测试数据验证三个角色、医院隔离、文件权限和护理闭环。

### 阶段 C：封闭试点

只邀请已签约医院和已授权宠主。验证医生签署方案、任务拆分、打卡、异常队列、方案版本更新和复诊结果。

### 阶段 D：正式上线

完成隐私合规、备份恢复、运行监控、客服机制和应急预案后，才提交小程序审核并扩大用户范围。

## 6. 本地安全配置与检查

在项目根目录执行：

```bash
cp .env.api.example .env.api
```

由负责人在本机编辑 `.env.api`，填入真实值。然后加载环境变量并执行：

```bash
set -a
source .env.api
set +a
pnpm backend:preflight
pnpm storage:bootstrap
pnpm api:check
pnpm api:test
```

首次建立管理账号时，临时提供 `ADMIN_EMAIL`、`ADMIN_PASSWORD`（至少12位）和 `ADMIN_DISPLAY_NAME`，执行：

```bash
pnpm admin:bootstrap
```

完成后立即从环境变量或临时配置中删除 `ADMIN_PASSWORD`。管理员密码、Service Role Key 和任何云密钥都不能提交到 Git。

启动 API：

```bash
pnpm api
```

检查：

```text
http://127.0.0.1:8787/api/v1/health
http://127.0.0.1:8787/api/v1/ready
```

`health` 只表示程序在运行；只有 `ready` 返回 `ready`，才表示数据库、微信、大模型和文件存储的关键配置都已提供。

## 7. 云服务器部署

服务器安装 Docker 后，把源代码和服务器上的 `.env.api` 放到项目目录，执行：

```bash
docker compose up -d --build
docker compose logs -f api
```

容器只监听服务器本机 `127.0.0.1:8787`。外部必须通过云负载均衡、Nginx 或 Caddy 提供 HTTPS，不能把 8787 端口直接暴露给小程序。

生产环境至少设置：

```text
NODE_ENV=production
API_HOST=0.0.0.0
CORS_ALLOWED_ORIGINS=https://管理后台正式域名
```

## 8. 上线验收标准

- 微信真机登录成功，宠主和医生自动进入各自页面。
- 未审核医生不能查看病例；不同医院无法互看病例。
- 宠主授权后，本院医生才能查看相应宠物。
- 医生签署护理方案后，宠主任务自动更新；AI不能自行改药或改诊断。
- 打卡永久保存，异常进入正确医生队列并产生处理留痕。
- 报告文件是私有的，未授权用户无法下载。
- 知识库只调用已审核条目，答案显示来源；无依据时明确拒答。
- 备份可恢复，用户可以撤回授权、导出和申请删除数据。
- `/ready` 正常，关键错误会通知技术负责人。

达到以上标准，才是“可封闭试用的产品”；通过真实试点和小程序审核后，才是“可公开使用的产品”。
