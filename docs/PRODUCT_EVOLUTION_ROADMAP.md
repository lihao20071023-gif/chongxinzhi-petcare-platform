# 宠馨智产品演进路线

## 阶段 1：微信小程序验证期（现在）

目标：用一个小程序验证宠主与医生的真实院后护理协同需求。

- 宠主与医生共用一个 AppID、一套代码和一个登录入口。
- 登录后由后端返回 `pet_owner` 或 `doctor`，前端按角色显示页面。
- 管理员使用独立 Web 后台，不进入微信小程序。
- 三端共用一套 API 与 PostgreSQL 数据库。
- 优先完成：真实登录、医院/医生审核、宠物档案、授权病例、医生护理方案、每日任务、打卡、异常提醒、知识库问答。
- 只收集完成服务所必需且经用户明确授权的数据，支持查看、导出、更正和撤回授权。

验收标准：至少 1 家真实合作医院、1 名执业兽医、10–20 个已确诊且明确授权的慢病病例，连续试用 30–60 天；能统计护理任务完成率、复诊率、异常响应时间和医生沟通耗时。

## 阶段 2：多端扩展期（比赛后）

前提：微信小程序已证明用户会持续记录，医院愿意持续使用。

- 优先用 uni-app 或 PWA 复用业务逻辑，覆盖微信小程序、H5 和轻量 App。
- 后端 API、数据库、权限与 AI 服务不重做，只增加客户端。
- 增加消息推送、弱网缓存、文件上传续传、数据导出和运营分析。
- 所有 AI 输出保存来源、模型版本、输入摘要、医生审核状态和生成成本。

验收标准：有稳定月活、连续留存和医院续费意愿；跨端用户确有规模，而不是为了“看起来像 App”重复开发。

## 阶段 3：原生 App 期（用户量足够时）

触发条件：硬件蓝牙、后台持续监测、音视频沟通或性能需求已无法由小程序/跨端框架稳定满足。

- iOS/Android 原生端重点承接蓝牙设备、后台任务、实时通信和更强的无障碍体验。
- 保持同一账号、同一病例、同一医院权限和同一 API。
- 不在验证需求前投入双端原生团队。

## 不变的产品核心

医生负责诊疗与治疗决策；宠馨智把医生确认的方案变成每日可执行任务，收集家庭记录、分析趋势、标记异常并回传医生。AI 不独立诊断、不自行改药，也不把演示数据当真实病例。
